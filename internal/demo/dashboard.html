Event log

    The DNS you would actually configure — none of it changes during failover

    
      
    The record set is published once: the failover hostname lists the origin
      at priority 1 and the peers sharing priority 2 — clients pick randomly among
      equal-priority records, so outage load spreads across the peer set instead of
      dogpiling one fallback (SVCB has no weights; that crude spreading is all this
      layer does, by design). Failing over needs no DNS edit, no
      health-checking brain, and no propagation wait — the client itself walks the
      list, MX-style (this page's walk proxy plays that browser role). Client support
      for RFC 9460 records still
      varies — there is no caniuse entry (the
      request has been open
      since 2021): Safari walks the full record set natively, Firefox uses HTTPS
      records when DoH is enabled, Chromium's use is partial (ALPN and ECH more than
      endpoint failover) — see this
      per-browser breakdown.
      Which is why the plain multi-A records stay in the set: every client falls
      back across those, just slower (8–30 seconds) — fine for a lights-on page, wrong
      for a real app. Peer agents recognize
      the member's hostname by Host/SNI and hold real certificates for it via the
      delegated _acme-challenge CNAME (DNS-01 through certmagic), so the member
      never shares a private key. The alternative — managed DNS that health-checks the
      origin and swaps a single answer — also works, but reintroduces an external
      brain; the MVP prefers the client-driven walk.
    
    
    What is real
    
      
    Every member card is two separate processes on two ports: the member's
      ordinary web server (nginx, httpd, IIS — whatever it already runs, labeled on
      each card) and the wreath-agent daemon beside it; kill either without the
      other. Bundles are built and Ed25519-signed over RFC 8785 canonical JSON,
      replicated by polling, verified — signature and monotonic version — before
      storing, and re-served by peers. The health matrix is the agents' own gossip,
      not this page's opinion. Timing is compressed: 2-second polls instead of
      30-plus.
    
    
    Setup & trust, in one breath
    
      
    A member generates a keypair; the wreath's signed registry records its
      public key and endpoints. Publishing = sign + place two static files under
      /.well-known/wreath/v0/ on your own site. Peers replicate but cannot forge:
      the worst a compromised peer can do is withhold or serve stale — and the matrix
      above catches both.
